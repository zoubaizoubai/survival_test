# 逻辑性能基线与验证

## 适用范围

`tests/run_tests.gd` 中的性能场景是 Godot 4.7 无头环境下的**逻辑微基准**。它用于在同一机器、同一 Godot 版本与同一 seed 下发现相对回归，不等价于真实渲染帧时间，也不能单独证明目标设备稳定 60 FPS。

基准不包括或不完整包括：

- GPU 渲染、CanvasItem 批处理与浏览器合成。
- 真实 SceneTree 完整帧调度、输入与音频开销。
- 不同移动芯片、浏览器、热限频与后台负载的影响。

## 基线场景

固定 seed 下覆盖前、中、后期与数量上限场景，压力组合包含大量敌人和掉落物。具体循环次数、数量上限与通过阈值以 `tests/run_tests.gd` 为唯一可执行来源，文档不复制易漂移的断言数量或毫秒数。

最近一次结果保存在 `tests/baseline.json`，可使用：

```bash
make perf
```

基线文件包含 Godot 版本、seed、时间戳、场景对象数与耗时分位数。由于系统调度与机器差异，不应将不同环境的绝对数值直接比较。

## 已采用的优化

1. **直接子节点查询**：敌人与掉落物容器提供活跃对象集合，减少高频 group 全树遍历。
2. **平方距离判定**：范围伤害、寻敌、磁吸与投射物碰撞避免不必要的开方。
3. **对象池**：投射物、掉落物与高频特效重用节点，降低分配与回收峰值。
4. **容量上限**：敌人、掉落物与部分视觉效果存在数量限制，避免无界增长。

上述优化必须由功能回归保护，不能以改变伤害范围、穿透、拾取或死亡语义换取基准数字。

## 回归流程

```bash
# 默认使用 seed=1337，并传入 isolated=true 避免触碰正式 user:// 数据
make test

# 需要复现其他 seed 时
make test SEED=42

# 查看最近基线
make perf
```

评估回归时：

1. 保持 Godot 版本、机器、电源模式和 seed 一致。
2. 多次运行，关注中位数和高分位数的稳定趋势，不以单次极值下结论。
3. 性能变化同时运行战斗、状态与边界回归。
4. 只在有意接受新基线时提交 `tests/baseline.json`。

## 目标设备验收

发版前还需在目标 Web 浏览器与代表性中端设备上采集真实帧时间，覆盖长局、Boss、上限敌人/掉落物和页面失去焦点后恢复等场景。设备型号、浏览器版本、分辨率、平均帧时间与高分位数应作为发布记录保存，而不是将某次本机无头结果写成设备性能保证。
