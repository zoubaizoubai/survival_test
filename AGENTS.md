# Repository Guidelines

## Project Structure & Module Organization

This Godot 4.7 game starts at `scenes/home.tscn`; `scenes/game.tscn` hosts gameplay. Logic lives in `scripts/` by node or feature. Keep `.gd.uid` files with their scripts. Agent and task configuration lives in `.agents/`, `.codex/`, and `.beads/`.

## Build, Test, and Development Commands

- `godot --editor --path .` opens the editor.
- `godot --path .` runs the main scene.
- `godot --headless --path . --quit` validates project loading.

Use Godot 4.7; no export preset or automated runner is committed.

## Coding Style & Naming Conventions

Match existing GDScript: tabs, typed signatures, two blank lines between functions, and trailing commas in multiline collections. Use `snake_case` for files and members, `PascalCase` for preloaded scripts, and `UPPER_SNAKE_CASE` for constants. Use `res://` paths; edit serialized scenes through Godot when practical.

## Testing Guidelines

Run the headless check; manually exercise movement, pause, upgrades, combat, and win/lose flow. Test UI at 1280×720 with touch/mouse input. Put future tests in `tests/` as `test_<feature>.gd` and document their runner.

## Commit & Pull Request Guidelines

History favors short, imperative subjects. Use `<type>: <summary>` (for example, `fix: clamp enemy spawn position`) and keep commits focused. Pull requests should describe behavior, link the Beads issue, list verification, and include screenshots or video for visual changes.

## Beads Issue Tracker

Use Beads (`bd`) for durable task tracking in repositories that include it. Use the `beads` skill at `.agents/skills/beads/SKILL.md` (project install) or `~/.agents/skills/beads/SKILL.md` (global install) for Beads workflow guidance, then use the `bd` CLI for issue operations.
只有明确需要改动代码时候才需要记录任务, 一般的对话/不牵涉到代码改动无需建立任务.

### Quick Reference

```bash
bd ready                # Find available work
bd show <id>            # View issue details
bd update <id> --claim  # Claim work
bd close <id>           # Complete work
bd prime                # Refresh Beads context
```

### Rules

- Use `bd` for all task tracking; do not create markdown TODO lists.
- Run `bd prime` when Beads context is missing or stale. Codex 0.129.0+ can load Beads context automatically through native hooks; use `/hooks` to inspect or toggle them.
- Keep persistent project memory in Beads via `bd remember`; do not create ad hoc memory files.

**Architecture in one line:** issues live in a local Dolt DB; sync uses `refs/dolt/data` on your git remote; `.beads/issues.jsonl` is a passive export. See https://github.com/gastownhall/beads/blob/main/docs/SYNC_CONCEPTS.md for details and anti-patterns.
